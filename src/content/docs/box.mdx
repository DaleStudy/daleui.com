Box는 가장 기본적인 레이아웃 컴포넌트입니다. 배치 규칙 없이 한 덩어리를 감싸거나 폭을 제한하고 싶을 때 쓰는 빈 상자입니다. `padding`·`margin`은 [스페이싱 토큰](/docs/spacing) 이름을 받고, `as`로 렌더링할 태그를 바꿔 `section`·`main` 같은 시맨틱 요소로도 쓸 수 있습니다.

## 렌더링 태그

`as`는 Box가 만들어 낼 HTML 태그를 고릅니다. 기본값은 `div`이고 `section`·`article`·`main`·`aside`·`header`·`footer`·`nav`·`span`을 받습니다. 받을 수 있는 값이 정해져 있어 임의의 태그나 다른 컴포넌트로는 바꿀 수 없습니다.

어떤 태그를 골라도 보이는 모습은 같지만 문서 구조는 달라집니다. 페이지의 큰 영역을 감쌀 때 `div` 대신 의미가 있는 태그를 고르면, 스크린 리더 사용자가 그 영역을 랜드마크로 건너뛸 수 있습니다.

<Example name="box-as" />

`as="span"`은 인라인 요소라서 `width`·`height`가 적용되지 않습니다. 문장 안의 짧은 구간을 감쌀 때만 쓰고, 크기를 정해야 하면 블록 태그를 고릅니다.

## 여백

`padding`은 안쪽, `margin`은 바깥 여백이고 둘 다 [스페이싱 토큰](/docs/spacing) 이름을 받습니다. `"0"` `"2"` `"4"` `"8"` `"12"` `"16"` `"20"` `"24"` `"32"` `"36"` `"40"` `"48"` 열두 개이며, 이름은 픽셀 값이지만 실제 값은 rem이라 사용자가 브라우저 글자 크기를 키우면 여백도 함께 늘어납니다.

여백은 네 면에 한꺼번에 들어갑니다. `paddingTop`이나 축별 값은 받지 않으므로, 한쪽 면만 띄워야 하면 `className`으로 스타일을 직접 얹습니다.

자체 여백이 없는 [Card](/docs/card) 안을 띄우는 것이 `padding`의 대표적인 쓰임새입니다.

`margin`은 상자 바깥을 띄웁니다. 다만 형제 요소 사이의 간격은 각자의 `margin`보다 부모의 `gap`으로 주는 편이 낫습니다. [Flex](/docs/flex)·[HStack](/docs/hstack)·[VStack](/docs/vstack)의 `gap`은 자식이 몇 개든 간격이 한 번만 정의되고, 세로로 맞닿은 `margin`끼리 합쳐지는 마진 상쇄도 생기지 않습니다.

## 크기

`width`·`height`는 토큰이 아니라 CSS 길이 문자열을 받습니다. `"360px"`·`"10rem"`·`"2em"`·`"50%"`처럼 `px`·`rem`·`em`·`%` 네 단위만 쓸 수 있고, `auto`나 `calc()`, `minmax()` 같은 값은 받지 않습니다. 본문 폭을 제한하는 `max-width`도 없으므로, 그런 제약이 필요하면 `className`으로 얹습니다.

두 값은 클래스가 아니라 인라인 `style`로 들어갑니다. 그래서 미디어 쿼리로 덮어쓸 수 없고, `style` prop을 직접 넘기면 그 객체가 통째로 자리를 차지해 `width`·`height`가 사라집니다. 화면 폭에 따라 크기를 바꿔야 한다면 `%`를 쓰거나 `className`으로 처리합니다.

## Props

| Prop      | 타입                                                                                      | 기본값  | 설명                              |
| --------- | ----------------------------------------------------------------------------------------- | ------- | --------------------------------- |
| `as`      | `"div"` `"section"` `"article"` `"main"` `"aside"` `"header"` `"footer"` `"nav"` `"span"` | `"div"` | 렌더링할 HTML 태그                |
| `padding` | 스페이싱 토큰 이름 (`"0"`–`"48"`)                                                         | 없음    | 네 면의 안쪽 여백                 |
| `margin`  | 스페이싱 토큰 이름 (`"0"`–`"48"`)                                                         | 없음    | 네 면의 바깥 여백                 |
| `width`   | `px`·`rem`·`em`·`%` 길이 문자열 (예: `"360px"`)                                           | 없음    | 너비, 인라인 `style`로 적용됩니다 |
| `height`  | `px`·`rem`·`em`·`%` 길이 문자열 (예: `"10rem"`)                                           | 없음    | 높이, 인라인 `style`로 적용됩니다 |
| `ref`     | `Ref<HTMLElement>`                                                                        | 없음    | 렌더링된 요소 참조                |

`className`과 `id`·`onClick`·`aria-*` 같은 나머지 HTML 속성은 렌더링된 요소로 그대로 전달됩니다. `className`은 Box가 만든 클래스 뒤에 붙으므로, 배경·테두리처럼 Box가 다루지 않는 스타일은 여기에 얹습니다.

## 사용 가이드

Box는 **배치 규칙이 필요 없을 때** 씁니다. 자식이 하나거나, 여러 개여도 흐름대로 쌓이기만 하면 되는 경우입니다. 자식을 늘어놓는 방향·정렬·간격을 정해야 하는 순간부터는 다른 컴포넌트가 맞습니다.

| 하려는 일                           | 쓰는 컴포넌트                                   |
| ----------------------------------- | ----------------------------------------------- |
| 한 덩어리에 여백·폭을 주기          | Box                                             |
| 시맨틱 태그로 영역 감싸기           | Box (`as`)                                      |
| 자식을 가로 한 줄·세로 한 열로 놓기 | [HStack](/docs/hstack) · [VStack](/docs/vstack) |
| 방향·정렬을 직접 정하기             | [Flex](/docs/flex)                              |
| 행과 열을 함께 정하기               | [Grid](/docs/grid)                              |
| 제목·설명·링크가 있는 카드 만들기   | [Card](/docs/card)                              |

흔한 오용은 세 가지입니다.

- **`gap` 대신 Box로 간격 만들기** — 자식마다 `margin`을 주거나 빈 Box를 끼워 넣는 대신 부모의 `gap`을 씁니다.
- **Flex·Grid 안을 Box로 한 번 더 감싸기** — Flex·Grid·HStack·VStack에도 `padding`과 `as`가 있습니다. 여백만 주려고 Box를 덧씌우면 요소만 늘어납니다.
- **스타일 전용 래퍼로 쓰기** — Box는 레이아웃만 다룹니다. 배경·테두리를 얹어 카드처럼 꾸미기 전에 [Card](/docs/card)로 되는 일인지 먼저 확인합니다.

## 접근성

키보드·포커스·명암비처럼 공통으로 지켜야 할 것은 [접근성 가이드](/docs/a11y-guide)에 있습니다. Box에서만 신경 쓸 점은 다음과 같습니다.

- Box는 기본값인 `div`로 렌더링되면 보조 기술에 아무 의미도 전달하지 않습니다. 영역을 구분하는 상자라면 `as`로 시맨틱 태그를 골라 랜드마크를 만듭니다.
- `as`로 시맨틱 태그를 골랐다면 `role`을 따로 주지 않습니다. `as="nav"`에 `role="navigation"`을 더하는 식의 중복 지정은 불필요합니다.
- `as="main"`은 한 페이지에 하나만 둡니다. `section`과 `article`은 여러 개 둘 수 있지만, 제목이 없는 `section`은 랜드마크로 읽히지 않으므로 안에 제목을 두거나 `aria-label`로 이름을 붙입니다.
- `height`로 높이를 고정하면 글자 크기를 키운 사용자에게 내용이 잘릴 수 있습니다. 텍스트를 담는 상자에는 높이를 고정하지 않습니다.
